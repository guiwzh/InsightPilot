# 部署

架构：Caddy（前端静态文件 + 反向代理，独占服务器时还负责自动 HTTPS）→ Node API → PostgreSQL，三个容器由 `docker-compose.prod.yml` 管理。

镜像在本机构建，再通过 ssh 传到服务器：服务器不需要构建（2G 内存够用），也不需要访问 Docker Hub（中国内地服务器经常拉不下来）。

两种模式：

| | 独占服务器 | 服务器上已有 Nginx Proxy Manager（当前线上用的） |
| --- | --- | --- |
| 80/443 | Caddy 直接监听 | NPM 监听，Caddy 不占端口 |
| HTTPS 证书 | Caddy 自动申请 | 在 NPM 管理界面申请 |
| 链路 | 浏览器 → Caddy → Node | 浏览器 → NPM → Caddy → Node |
| 发布命令 | `deploy.sh app` | `DEPLOY_WITH_NPM=1 deploy.sh app` |

NPM 模式下，`deploy/compose.npm.yml` 把 web 容器接入 NPM 所在的 Docker 网络（别名 `insightpilot-web`），NPM 按容器名转发过来。

## 首次部署

1. **服务器准备**
   - 安装 Docker 和 Docker Compose 插件。
   - 安全组放行 22、80、443 端口。
   - 域名解析到服务器 IP。中国内地服务器用域名对外提供服务需要 ICP 备案。
2. **在服务器上创建 `/opt/insightpilot/.env`**（只放在服务器上，不进 git，`chmod 600`）：

   ```bash
   POSTGRES_USER=insightpilot
   POSTGRES_PASSWORD=<随机生成，openssl rand -hex 16>
   POSTGRES_DB=insightpilot
   ANALYST_RO_PASSWORD=<随机生成，openssl rand -hex 16>
   DEEPSEEK_API_KEY=<你的 key>
   MODEL_FAST=deepseek-flash
   MODEL_STRONG=deepseek-v4-pro
   CHAT_RATE_LIMIT_PER_MINUTE=10
   VISITOR_DAILY_TOKENS=400000
   SITE_DAILY_BUDGET_CNY=10

   # 独占服务器：写域名，Caddy 自动申请证书
   SITE_ADDRESS=insight.example.com
   COMPOSE_FILE=docker-compose.prod.yml

   # 已有 NPM：换成下面这几行。Caddy 只监听容器内的 80，宿主机端口只绑 127.0.0.1，供在服务器上调试
   # SITE_ADDRESS=:80
   # WEB_BIND=127.0.0.1
   # HTTP_PORT=18080
   # HTTPS_PORT=18443
   # PROXY_NETWORK=<NPM 所在的网络，docker network ls 查看>
   # COMPOSE_FILE=docker-compose.prod.yml:compose.npm.yml
   ```

   两个密码都会拼进数据库连接串（`postgres://用户:密码@…`），只用字母和数字；含 `@`、`/`、`:` 这类字符时连接串会解析错。

   `COMPOSE_FILE` 让你在服务器上直接执行 `docker compose ps/logs/up`，不用每次都写 `-f`。服务器上没有默认名字的 `docker-compose.yml`，不设置它的话，下面的回滚、备份命令会报 `no configuration file provided`。发布脚本自己带 `-f`，不受它影响。`TAG`（当前版本）由发布脚本写入，不用手动加。

3. **发布应用**：在本机仓库根目录执行 `DEPLOY_HOST=root@<IP> ./scripts/deploy.sh app`（NPM 模式前面加 `DEPLOY_WITH_NPM=1`）。
4. **导入样例数据**：`DEPLOY_HOST=root@<IP> ./scripts/deploy.sh data`（NPM 模式同样加 `DEPLOY_WITH_NPM=1`）。这一步会顺带把只读账号 `analyst_ro` 的密码改成 `.env` 里的值。
5. **（仅 NPM 模式）配置 NPM**：在管理界面添加 Proxy Host：
   - Domain：你的域名；Scheme `http`；Forward Hostname `insightpilot-web`；Forward Port `80`。
   - SSL 页：申请 Let's Encrypt 证书，勾选 Force SSL、HTTP/2。
   - 不需要额外配置关闭缓冲：AI SDK 的流式响应自带 `X-Accel-Buffering: no`，nginx 看到这个头就不会缓冲 SSE。
6. 打开 `https://<你的域名>`，顶栏显示"数据库已连接""样例数据已就绪"即成功。

在服务器上自检（不经过域名）：

```bash
# 两种模式都适用：在 server 容器里直接请求 API
docker compose exec server node -e "fetch('http://127.0.0.1:8787/api/health').then((r) => r.text()).then(console.log)"
# NPM 模式也可以走 Caddy，端口是 .env 里的 HTTP_PORT
curl -s 127.0.0.1:18080/api/health
```

## 日常发布

```bash
DEPLOY_HOST=root@<IP> DEPLOY_WITH_NPM=1 ./scripts/deploy.sh app   # 独占服务器去掉 DEPLOY_WITH_NPM=1
```

镜像标签是 git commit 的短哈希（有未提交的改动时再加时间戳），服务器上已有的镜像不会重复上传。

**回滚**：把服务器 `.env` 里的 `TAG` 改成旧版本，然后执行 `cd /opt/insightpilot && docker compose up -d`。`docker images insightpilot-server` 可以看到服务器上有哪些版本。

## 备份

建议在服务器上加一条每日定时任务，备份 app 数据（会话、日志）：

```bash
0 4 * * * cd /opt/insightpilot && docker compose exec -T postgres pg_dump -U insightpilot -d insightpilot -n app -Fc > /opt/insightpilot/backup-$(date +\%F).dump
```

shop 是样例数据，丢了可以重新导入。

## 注意

- **表结构变更**：服务器上没有 drizzle-kit。本机 `pnpm db:push` 之后，要把对应的 SQL 在服务器上执行一遍，或者重新导出 app 的表结构。
- **init.sql 只在数据库第一次初始化时执行**：如果第一次失败了（比如文件读不了），数据目录已经建好，之后重启不会再执行。要先 `docker compose down`，再 `docker volume rm insightpilot-prod_pgdata` 删掉空的数据卷重来。
- **服务器的 umask**：阿里云的镜像里 root 的 umask 是 027，scp 上去的文件别的用户读不了，容器里的 postgres 用户读不了 init.sql。发布脚本会把它改成 644。
- **证书**（独占模式）：Caddy 的证书存在 `caddy_data` 数据卷里，删掉这个卷会触发重新申请。频繁重新申请可能触发 Let's Encrypt 的频率限制。
- **限流识别真实 IP**：从 `X-Forwarded-For` 的右边往左找第一个公网地址，跳过 NPM 和 Caddy 这些内网代理（见 `apps/server/src/middleware/client-ip.ts`）。所以 Node 不能直接暴露在公网，compose 里没有映射它的端口。
- **内存**：2G 的机器上还跑着别的服务，三个容器都设了 `mem_limit`（320M / 320M / 64M），Postgres 的缓存和连接数也调小了。
- **DeepSeek 余额**：余额偏低时，DeepSeek 会降低并发上限（评测时实测被限到 5 个并发）。上线前要确保余额充足。
