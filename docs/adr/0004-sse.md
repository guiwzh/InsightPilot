# 0004 流式输出用 SSE

**背景**：大模型输出要逐字展示，可以用 SSE，也可以用 WebSocket。

**决定**：用 SSE（AI SDK 的 UI Message Stream）。

**理由**
- 数据只需要服务端到客户端单向流动，用户的新消息是一个新的 POST 请求，不需要双向通道。
- 就是普通 HTTP：能走现有的鉴权、限流、日志中间件，CDN 和代理都支持，不用维护连接状态和心跳。
- 前端停止生成就是断开请求，服务端通过 `abortSignal` 同步中断模型调用，不再继续计费。

**注意**：反向代理默认可能会缓冲响应。Nginx 要关掉 `proxy_buffering`（AI SDK 也会返回 `X-Accel-Buffering: no`）；Caddy 遇到 `text/event-stream` 会立即转发。实测经过 Caddy 后分 87 块逐步到达，没有被攒住。

**代价 / 何时推翻**：需要服务端主动推送（多人协作、实时通知）或者很高频的双向交互时，用 WebSocket。
