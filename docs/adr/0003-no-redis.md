# 0003 不引入 Redis

**背景**：常见方案会用 Redis 做语义缓存、限流计数、会话存储。

**决定**：不用 Redis。
- 查询结果缓存在 PostgreSQL 的 `app.query_results`；
- 限流用进程内存里的固定窗口计数；
- 每日预算从 `agent_runs` 实时汇总；
- DeepSeek 自带的前缀缓存承担了大部分省钱的工作（命中率约 89%）。

**理由**：单机部署、单进程，Redis 带来的收益很小，却多一个要运维的组件。2G 内存的服务器也不富裕。

**代价 / 何时推翻**：多实例部署时，内存限流不再准确，需要换成 Redis 之类的共享存储；流式响应的断线续传（AI SDK 的 resumable stream）也依赖 Redis。
