# 0001 后端用 Hono

**背景**：我是前端出身，后端越简单越好；后端只做三件事：转发对话、执行工具、记日志。

**决定**：用 Hono（Node 适配器），不用 NestJS，也不用 Express。

**理由**
- 基于 Web 标准的 `Request` / `Response`：AI SDK 返回的流式 `Response` 可以直接 `return`，不需要适配。
- 中间件、路由、类型推导都很轻，整个后端 8 个接口，每个几十行。
- NestJS 的依赖注入、模块、装饰器对这个规模是负担；Express 对流式响应和类型支持都不如 Hono。

**代价 / 何时推翻**：没有 NestJS 那样的分层约束，项目变大、多人协作时需要自己约定目录结构；如果要做复杂的权限体系、大量 CRUD，可以考虑 NestJS。
